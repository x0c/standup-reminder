# 排「装了但不响」与「离开后计时不清零」

## 文档定位

覆盖本工具两类现场问题：装上后从未提醒；锁屏/屏保后倒数还在走。对照现象、原因、处理。不替代连续使用计时、安装常驻两份知识库。

## 先跑

```bash
standup-reminder doctor
standup-reminder status
tail -20 "$HOME/Library/Application Support/standup-reminder/run.log"
```

`doctor` 退出码 0 且文案为正在计时，才算健康。

## 常见因果

1. **进程在跑、日志只有「启动」、从未「开始计时」**  
   现象：几天都没有提醒。  
   原因：把「前台应用名解析失败」当成了锁屏（v0.1.0）。  
   处理：升级到 v0.2.0+；判断失败必须按正在使用处理。装完用 `doctor` 确认。

2. **`status` 只说在运行，看不出下一次何时响**  
   现象：用户以为坏了。  
   原因：没有把计时进度写到状态文件。  
   处理：看 `status` 的连续使用分钟数；日志应有「计时中」心跳。

3. **`stop` 之后又自己起来**  
   现象：以为停了。  
   原因：登录项保活会把进程拉回来。  
   处理：`standup-reminder stop` 必须同时卸登录项。

4. **Homebrew 和手动安装同时在**  
   现象：重复拉起或行为怪异。  
   原因：两套登录项。  
   处理：只留一种。`doctor` 会提示。本机留安装脚本。

5. **藏窗口失败，但弹窗/屏保有了**  
   现象：提醒出了，窗口还在。  
   原因：辅助功能未授权，不影响弹窗和屏保。  
   处理：不把辅助功能当硬门槛；`now` 仍应能弹出对话框。

6. **热角开屏保 / 进锁屏后计时没有清零**  
   现象：人已经离开屏幕超过 3 分钟，倒数还在走。  
   原因：v0.2.0 只认旧的屏保进程名；新系统热角屏保不走那个名字。合盖休眠会走「系统唤醒」，看起来像清零了，但**不是**热角路径。  
   处理：升级到 v0.2.1+。离开必须看系统锁屏标记和屏保是否在跑。  
   验收分两档：
   - 认出离开：触发角开屏保，停满 20 秒，日志须有「检测到离开（screensaver）」或「（locked）」。停不够 20 秒会被漏扫。
   - 确认清零：须停满 **3 分钟** 再解锁，日志须有「离开已满3分钟，计时已重置」。20 秒内解锁出现「短离开未满3分钟，继续计时」是防抖，不是没修好。

7. **人还坐着，自动熄屏后计时从零开始**  
   现象：没起身，只是几分钟没碰键鼠，屏幕灭了再亮，倒数没了。  
   原因：v0.2.1 把熄屏/登录画面当成立刻离开。本机熄屏常是 5 分钟没操作。  
   处理：升级到 v0.2.2+。离开未满 3 分钟回来必须接着计。日志对照：先有「检测到离开…未满3分钟回来则继续计时」，亮屏后「短离开未满3分钟，继续计时」，中间不能出现「离开已满3分钟」。

8. **改了间隔，后台还按旧的响**  
   现象：命令显示已经是 80 分钟，实际仍约 1 小时就打断。  
   原因：旧版把间隔写在登录项环境变量里，环境变量会盖住配置文件。  
   处理：升级到 v0.3.0+，用 `standup-reminder config set interval 80m`。不要再改登录项。覆盖安装会把旧登录项里的间隔迁到配置文件。
