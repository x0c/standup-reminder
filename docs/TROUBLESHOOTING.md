# 排「装了但不响」与「离开后计时不清零」

改锁屏/屏保判断、安装自检，或用户说「从来没响过 / 锁屏了倒数还在走」时 **必读**。只看进程在不在会误判成已经生效。

## 先跑

```bash
standup-reminder doctor
standup-reminder status
tail -20 "$HOME/Library/Application Support/standup-reminder/run.log"
```

`doctor` 退出码 0 且文案为正在计时，才算健康。

## 常见因果

1. **进程在跑、日志只有「启动」、从未「开始计时」**  
   现象：几天都没有提醒。  
   原因：把「前台应用名解析失败」当成了锁屏（v0.1.0）。  
   处理：升级到 v0.2.0+；判断失败必须按正在使用处理。装完用 `doctor` 确认。

2. **`status` 只说在运行，看不出下一次何时响**  
   现象：用户以为坏了。  
   原因：没有把计时进度写到状态文件。  
   处理：看 `status` 的连续使用分钟数；日志应有「计时中」心跳。

3. **`stop` 之后又自己起来**  
   现象：以为停了。  
   原因：登录项保活会把进程拉回来。  
   处理：`standup-reminder stop` 必须同时卸登录项。

4. **Homebrew 和手动安装同时在**  
   现象：重复拉起或行为怪异。  
   原因：两套登录项。  
   处理：只留一种。`doctor` 会提示。

5. **藏窗口失败，但弹窗/屏保有了**  
   现象：提醒出了，窗口还在。  
   原因：辅助功能未授权，不影响弹窗和屏保。  
   处理：不把辅助功能当硬门槛；`now` 仍应能弹出对话框。

6. **热角开屏保 / 进锁屏后计时没有清零**  
   现象：人已经离开屏幕，倒数还在走。  
   原因：v0.2.0 只认旧的屏保进程名；新系统热角屏保不走那个名字。合盖休眠会走「系统唤醒」，看起来像清零了，但**不是**热角路径。  
   处理：升级到 v0.2.1+。离开必须看系统锁屏标记和屏保是否在跑。验收：触发角开屏保，在画面上停满 20 秒再解锁；日志须有「检测到离开（screensaver）」或「（locked）」，随后「检测到解锁，开始计时」。停不够 20 秒会被漏扫，不能据此判断修好或没修好。
